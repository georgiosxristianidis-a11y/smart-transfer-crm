# Gemini: Execution & Double Verification (DV) Protocol

> **Цель:** безошибочное исполнение всех карточек проекта — store, view, тесты, безопасность, рефактор — единственным исполнителем, без галлюцинаций, регрессий и ленивого кода.
> **Базовый принцип:** качество > скорость. "Done" — гипотеза, пока машинный гейт не вернул `0 failures`.
> **Слой:** подчинён `GEMINI.md` в корне репозитория. При конфликте побеждает корневой файл.

---

## 1. 🛡️ Архитектурные табу (Hard Constraints)

1. **Изоляция Store/View (`CLAUDE.md:13`)**:
   - Файлы `*.store.js` содержат **только чистую бизнес-логику и данные**.
   - **Строго запрещено** обращаться к DOM (`document`, `window`, `HTMLElement`, `querySelector`, `innerHTML`) внутри Store.
   - Файлы `*.view.js` отвечают за DOM, события и Chart.js, но **не производят расчет налогов, долей и бизнес-метрик**.
2. **Защита от XSS и Raw innerHTML (`CLAUDE.md:14`)**:
   - Запрещено прямое присваивание `element.innerHTML = ...`.
   - Использовать только теговый шаблон `html\`...\`` из `shared/utils.js` или `textContent`.
3. **Запрет Hex-цветов в JS (`CLAUDE.md:15`)**:
   - Цвета и шрифты берутся **исключительно** из `css/tokens.css`.
   - Запрещено хардкодить hex-цвета (например, `#FF4D88`, `#00E5FF`) в JS-коде.
4. **Соблюдение лимитов документации (`check-docs-budget.mjs`)**:
   - Карточки задач (`docs/handoff/cards/*.md`) не должны превышать лимит символов (cap 2000 chars).
   - Запрещено раздувать отчеты водой — только сухие факты и чеклист.

## 2. 🚫 Zero-Lazy, Token Hygiene & Surgical Policy

* **Тотальный запрет на плейсхолдеры**:
  Категорически запрещено использовать сокращения вида:
  `// ... existing code ...`, `// TODO: implement`, `/* unchanged */`, `// ... остальной код`.
  Каждая замена через `replace_file_content` должна содержать **полный, рабочий, готовый к исполнению блок**.
* **Хирургическая точность (Payload Optimization)**:
  Не перезаписывать весь файл целиком (`write_to_file` на существующий файл запрещен). Читать только необходимые диапазоны строк (`offset/limit`), искать через целевой `grep_search`.
* **Глушитель терминала (Terminal Silencer)**:
  Запрещено засорять контекст длинными выводами. Использовать тихий режим (`npm test --silent`, `git log -n 5 --oneline`). При ошибках фиксировать только блок Root-Cause и стек-трейс.
* **Двухфазный Session Guard**:
  - На 80% лимита шагов сессии: завершить текущий шаг, зафиксировать состояние в микро-хендофф (`cards/*.md`) и не начинать новые подзадачи.
  - На 100% лимита: аппаратный стоп.
* **Сохранение контекста**:
  Запрещено удалять существующие обработчики событий, комментарии и JSDoc, если это прямо не указано в скоупе задачи.

## 3. 🧠 Zero-Hallucination Guard (Защита от выдуманного кода)

1. **Запрет новых зависимостей**: Запрещено устанавливать новые npm-пакеты. Решения строятся на нативном ESM Vanilla JS и существующих модулях.
2. **Запрет выдуманных API**: Запрещено вызывать методы, которых нет в стандартных спецификациях или в локальных модулях.
3. **Переиспользование `shared/utils.js`**:
   - Для дат: `localDateKey(d)` и `parseLocalDate(s)`.
   - Для HTML: `html\`...\`` и `esc(str)`.
   - Для форматирования: `formatEUR(num)`.
4. **Проверка сигнатур перед вызовом**: Всегда проверять актуальный экспорт функции перед ее импортом.

## 4. 🔬 Протокол Double Verification & Proof-over-Trust (DV)

Перед началом работы и перед сдачей задачи **обязательно** выполнить 5 шагов:

0. **Ingest Memory (`.gemini/memory/lessons.md`)**:
   Прочитать накопленные уроки. Проверить скоуп задачи на известные подводные камни.
1. **Pre-Flight Grep & Invariant Check**:
   Убедиться через `grep_search` / `view_file`, что целевой код и символы физически существуют.
2. **Соблюдение Scope & STOP**:
   Ни при каких обстоятельствах не редактировать файлы вне поля `Scope`. При обнаружении второго бага — зафиксировать в карточке и не трогать.
3. **Запуск автоматических гейтов (Machine Verification)**:
   ```bash
   # Запуск из директории calculator:
   node ../.gemini/scripts/gate-dv.mjs
   npm test --silent
   node scripts/check-docs-budget.mjs
   ```
   **Критерий готовности:** все три команды завершились с кодом `0` (0 errors / 0 failures).
4. **Proof-over-Trust Evidence**:
   В карточке задачи зафиксировать точные команды проверки, код возврата и результат `0 failures`. Отчёты без консольных команд признаются недействительными.

## 5. 🔒 Аппаратная защита (Git Pre-Commit Hook)

В репозитории активен `.githooks/pre-commit` (`git config core.hooksPath .githooks`) — версионируется вместе с кодом и переживает клонирование. Блокирует коммит при:
- Попытке коммита напрямую в ветку `master`.
- Наличии хотя бы одной ошибки в `gate-dv.mjs` (DOM leak, innerHTML, Hex colors, lazy comments).
- Падении любого теста из тестового сьюта `npm test`.
- Превышении лимита размера документации `check-docs-budget.mjs`.
- Найденном чужом символе (`FOREIGN_ORIGIN`): импорт из athlete-pro и прочих проектов.

После успешных проверок хук сам поднимает patch-версию (`scripts/bump-version.mjs --staged`) и перегенерирует `sw.js`. Руками версию и `CACHE_NAME` не трогать.

## 6. ⚡ Единственный исполнитель и Smart Triage

Второй модели в контуре нет. Раньше страховкой был односнимковый аудит Sonnet по
`.gemini/handoff/ready_for_review.md`; теперь страховка машинная — гейты, тесты с
прибитыми числами и Import Firewall. Скрипт `prep-review.mjs` остаётся как
инструмент самопроверки перед PR, а не как передача эстафеты.

### А. Матрица классификации задач

| Категория | Риск | Что дополнительно обязательно |
| :--- | :---: | :--- |
| **Деньги и налоги (`CALC-*`)** | 🔴 HIGH | Ставку задаёт OWNER в карточке. Тест с литеральным числом пишется и коммитится **до** реализации |
| **Схема данных и бэкапы (`DATA-*`)** | 🔴 HIGH | Миграция вверх и проверка отказа на неизвестной будущей версии — в тестах |
| **Безопасность / CSP** | 🔴 HIGH | Диф CSP приводится в карточке дословно; ослабление политики — эскалация к OWNER |
| **Удаление мёртвого кода, CSS-токены, микрокопирайт** | 🟢 LOW | Обычные гейты, прямой мерж |

### Б. Эскалация к OWNER (не решать самому)

Число вкладок · стартовая вкладка · позиции фиксированных кнопок · схема данных ·
любая налоговая ставка или комиссия · ослабление CSP · новая npm-зависимость.
Эскалация — это строка в карточке и остановка, а не догадка.

### В. Импорт чужого опыта

Правило и список запрещённых символов: `GEMINI.md` §3 «Import Firewall».
Переносится принцип, не переносится ничего, что можно вставить в `grep`.
