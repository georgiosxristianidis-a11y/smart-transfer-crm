# 11 — Демо-данные о заправках попадают к реальному пользователю

**Приоритет:** P2 · **Область:** Данные · **Оценка:** 1 ч

## Проблема

`fuel.store.js:21-25`: если в localStorage пусто, возвращаются **выдуманные записи**:

```js
return [
  { id: 'fuel-1', date: ..., amount: 50, liters: 26.3, odo: 142500, station: 'BP Heraklion' },
  { id: 'fuel-2', date: '2026-08-10', ..., odo: 141950, station: 'Shell Airport' }
];
```

Первый запуск приложения → водитель видит €140 расходов на топливо, которых не было.
Он либо поверит цифрам (испорченная отчётность), либо потеряет доверие к приложению.
Пустое состояние должно быть пустым.

## Проблема 2: расхождение схемы

Демо-записи содержат поле `odo` (одометр), а `addFuelLog` (`fuel.store.js:56-63`)
его не пишет вовсе. Значит через две реальные заправки поле пропадёт из данных,
и любой будущий расчёт «литров на 100 км» по одометру молча получит `undefined`.
Либо поле нужно — тогда его надо принимать в форме, либо не нужно — тогда убрать.

## Проблема 3: жёстко зашитая цена топлива

`fuel.store.js:53`: `cost / 1.90` — «средняя цена по Греции». При этом в
`calculator.store.js:17` есть настраиваемое поле `fuelPrice: 1.78`. Два разных числа
для одной сущности в одном приложении: расчёт литров по заправке и расчёт юнит-экономики
разойдутся. Источник должен быть один.

## Что сделать

1. Убрать демо-массив. Пустое состояние — пустой список + осмысленный empty state
   («Записей о заправках нет. Добавьте первую»), как уже сделано для поездок
   (`trips.view.js:414`).
2. Решить судьбу `odo`: добавить поле в форму заправки (и считать по нему реальный
   расход л/100 км — это самая ценная метрика для водителя) либо удалить из демо.
3. Брать цену топлива из `CalculatorStore.state.fuelPrice`, а не из литерала `1.90`.
4. Заодно: `fuel.store.js:1` импортирует `DB` и не использует — удалить или
   довести переезд на IndexedDB (карточка 05).

## Критерий приёмки

Чистый профиль браузера → вкладка «Топливо» показывает нули и empty state,
а не €140 из ниоткуда.
