# 05 — Нет резервной копии: данные бизнеса теряются молча

**Приоритет:** P0 · **Область:** Данные / «backend» · **Оценка:** 3–4 ч

## Проблема

Настоящего бэкенда нет — и это нормальный выбор для этого продукта. Не нормально то,
что хранилище расщеплено на три несвязанных места без версий, миграций и бэкапа:

| Данные | Где | Ключ |
|--------|-----|------|
| Поездки | IndexedDB | `UnitCalcDB` / `trips`, `DB_VERSION = 1` |
| Заправки | localStorage | `smart_transfer_fuel_logs_v1` |
| Настройки калькулятора | localStorage | `taxi_calc_state` |

Последствия:

1. **Молчаливая потеря.** Браузер вытесняет IndexedDB под давлением на диск,
   `Clear site data` сносит всё, переустановка PWA — тоже. `navigator.storage.persist()`
   нигде не запрашивается. Вся история трансферов за сезон исчезает без предупреждения.
2. **Нет полного экспорта.** `exportCSV` выгружает только поездки, без заправок и настроек,
   и импорта не существует — CSV не является резервной копией.
3. **Нет версии схемы.** `loadFromStorage` (`calculator.store.js:69-80`) делает
   `{...this.state, ...JSON.parse(saved)}` без валидации. Сохранённый год назад объект
   с переименованными полями тихо смешается с дефолтами и даст неверные деньги на экране.
   `DB_VERSION = 1` никогда не поднимался — путь миграции не проверен ни разу.
4. **Мёртвый импорт.** `fuel.store.js:1` импортирует `DB`, но не использует —
   след недоделанного переезда заправок в IndexedDB.

## Что сделать

1. **Единый бэкап.** Кнопка «Экспорт всех данных» → один JSON:
   `{ schemaVersion: 2, exportedAt, trips: [], fuelLogs: [], calcState: {} }`.
   Плюс «Импорт» с превью и подтверждением перезаписи. Это и есть страховка.
2. **Версия схемы.** Поле `schemaVersion` в каждом хранилище + функция `migrate(from, to)`.
   При неизвестной будущей версии — не смешивать, а показать явную ошибку.
3. **Persistent storage.** Запросить `navigator.storage.persist()` при первом сохранении
   поездки; показать статус квоты в настройках.
4. **Свести заправки в IndexedDB** (объектное хранилище `fuel`, `DB_VERSION = 2`) —
   и заодно проверить миграцию на реальных данных. Либо убрать мёртвый импорт `DB`.
5. Заменить `generateId()` (`trips.store.js:30-32`, использует устаревший `substr`)
   на `crypto.randomUUID()`.

## Критерий приёмки

Экспорт → `Clear site data` → импорт → состояние приложения идентично исходному
(поездки, заправки, настройки калькулятора).
