# 03 — «Следующий трансфер» показывает прошедшую поездку

**Приоритет:** P0 · **Область:** Бизнес-логика · **Оценка:** 30 мин

## Проблема

`trips.store.js:109-113`:

```js
getNextUpcomingTrip() {
  const activeTrips = this.trips.filter(t => t.status !== 'completed');
  if (activeTrips.length === 0) return null;
  return activeTrips[0];
}
```

`this.trips` отсортирован по возрастанию даты. Значит `[0]` — **самая старая** активная
поездка, а не ближайшая будущая. Стоит водителю забыть свайпнуть вчерашний трансфер —
и hero-карточка «СЛЕДУЮЩИЙ ТРАНСФЕР», и полноэкранный HUD намертво залипают на вчера.
На практике это происходит постоянно: отмена статуса — ручное действие.

Тест `trips.store.test.js:104-120` фиксирует именно это поведение (обе поездки в будущем,
поэтому баг не виден) — то есть тест закрепляет дефект.

## Что сделать

```js
getNextUpcomingTrip(now = new Date()) {
  return this.trips.find(t =>
    t.status !== 'completed' && new Date(`${t.date}T${t.time || '00:00'}`) >= now
  ) || null;
}
```

Параметр `now` — чтобы тест не зависел от системных часов.

Отдельно решить продуктовый вопрос: просроченные активные поездки не должны исчезать
молча. Нужен явный блок «Просрочено» над списком, либо авто-перевод в статус `missed`
через сутки. Сейчас они просто накапливаются невидимо.

## Критерий приёмки

Тест: три поездки — вчера (pending), сегодня +2 ч, завтра. `getNextUpcomingTrip()`
возвращает сегодняшнюю. Вчерашняя видна в UI как просроченная.
