# 04 — Таймзона: UTC-даты используются как местные (Крит = UTC+3)

**Приоритет:** P0 · **Область:** Бизнес-логика · **Оценка:** 1–2 ч

## Проблема

По коду разбросан паттерн `new Date().toISOString().split('T')[0]` — он даёт дату
**в UTC**, а не в часовом поясе водителя:

- `app.js:25` — «сегодня» для статистики в шапке
- `trips.view.js:51, 133` — дефолт в поле даты новой поездки
- `fuel.store.js:23, 58, 79` — дата записи о заправке

Крит летом — UTC+3. Каждый день с 00:00 до 03:00 по местному времени приложение считает,
что «сегодня» — это ещё вчера. Ночные трансферы из аэропорта (основной поток) попадут
в неверные сутки: выручка за сегодня в шапке занижена, дата в форме подставлена
вчерашняя, заправка записана не в тот день.

Зеркальная проблема — `new Date(t.date)` для строки `'2026-08-14'`
(`app.js:29`, `trips.store.js:100`, `fuel.store.js:94`): по спецификации это парсится
как **UTC-полночь**, а `.getMonth()` / `.getFullYear()` читают уже в локальном поясе.
Для UTC+3 совпадает, но для любого отрицательного смещения даёт сдвиг месяца на границе —
1 августа попадёт в июль.

## Что сделать

1. Добавить в `shared/utils.js` две функции и использовать только их:

```js
export const localDateKey = (d = new Date()) =>
  `${d.getFullYear()}-${String(d.getMonth() + 1).padStart(2, '0')}-${String(d.getDate()).padStart(2, '0')}`;

export const parseLocalDate = (key) => {
  const [y, m, day] = key.split('-').map(Number);
  return new Date(y, m - 1, day);      // локальная полночь, не UTC
};
```

2. Заменить все шесть вхождений `toISOString().split('T')[0]` на `localDateKey()`.
3. Заменить `new Date(t.date)` на `parseLocalDate(t.date)`.
4. Проверить `generateGCalLink` (`trips.store.js:115-128`): там `toISOString()` **уместен** —
   Google Calendar ждёт UTC. Не трогать. Но при пустом `trip.time` `new Date('2026-08-14T')`
   даёт `Invalid Date`, и `.toISOString()` выбрасывает `RangeError` — добавить фолбэк.

## Критерий приёмки

Тест с зафиксированным временем 01:30 по местному: `localDateKey()` возвращает сегодняшнюю
местную дату, а не вчерашнюю UTC. Прогон `npm test` при `TZ=America/New_York` — зелёный.
