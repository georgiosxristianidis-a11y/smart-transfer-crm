# 09 — View-слой (~800 строк) без единого теста, часть проверок фиктивны

**Приоритет:** P1 · **Область:** Тесты · **Оценка:** 3–4 ч

## Проблема

`npm test` — 11 тестов, все зелёные (проверено). Но покрыт только Store-слой.
Без тестов остаются:

| Файл | Строк | Покрытие |
|------|-------|----------|
| `trips.view.js` | 443 | 0% |
| `calculator.view.js` | 227 | 0% |
| `fuel.view.js` | 127 | 0% |
| `shared/utils.js` (эскейпер `html`) | 34 | 0% |

Особенно тревожит `utils.js`: это **единственный рубеж защиты от XSS** (см. карточку 06),
и он не покрыт ничем. При этом он уже ломался — коммит `3faa988` («render source icon SVG
via SafeHTML to prevent HTML text escaping») и `b094b64` («SafeHTML class prevents
double-escaping») чинили именно его. Дважды сломанный и до сих пор не покрытый модуль.

Слабые места существующих тестов:
- `trips.store.test.js:104-120` — фиксирует **баг** из карточки 03 как ожидаемое поведение.
- `trips.store.test.js:146-148` — `assert.ok(metrics.todayAmount >= 50)`: проходит при
  любом значении ≥ 50, включая неверное. Нужны точные значения на фиксированных данных.
- `trips.store.test.js:66-68` — тест GCal сам признаёт, что не проверяет главное
  (конвертацию времени), потому что зависит от таймзоны машины. Чинится инъекцией `now`.
- Тесты делят один процесс и реальный `localStorage`-фолбэк — `FuelStore` в тесте видит
  демо-данные (см. карточку 11), отсюда и нестрогие ассерты.

## Что сделать

1. **`utils.test.js` в первую очередь.** Кейсы: `<script>`, `"`, `'`, `&`, `null`,
   `undefined`, вложенный `SafeHTML` (не должен экранироваться повторно), массив значений,
   и главное — попытка инъекции через атрибут: `html\`<a href="${userInput}">\``
   с `userInput = '" onmouseover="alert(1)'`.
2. Перевести View-тесты на `node --test` + `jsdom` (или Playwright, если нужен реальный
   свайп и View Transitions). Минимум: рендер списка из 3 поездок, XSS-имя клиента
   не исполняется, свайп вправо → `completed`.
3. Убрать нестрогие `>=`-ассерты, задать детерминированные входные данные.
4. Добавить `node --test --experimental-test-coverage` и порог покрытия в `npm run check`.

## Критерий приёмки

Тест на XSS через атрибут падает на текущей реализации `html`, если её намеренно
испортить, и проходит на исправной. Покрытие `shared/` — 100%.
