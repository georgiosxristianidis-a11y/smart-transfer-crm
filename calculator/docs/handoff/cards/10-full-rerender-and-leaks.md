# 10 — Полный ре-рендер `innerHTML` и подписки без отписки

**Приоритет:** P1 · **Область:** Производительность / UX · **Оценка:** 2–3 ч

## Проблема 1: список пересобирается целиком

`trips.view.js:420-493` на любое изменение store делает
`this.els.list.innerHTML = trips.map(...).join('')` — весь список уничтожается
и создаётся заново. Следствия на реальном сезоне (сотни поездок):

- **Свайп рвётся.** Если store обновится во время жеста, `draggingElement`
  (`trips.view.js:217`) указывает на удалённый узел; `setPointerCapture` уже потерян.
- **Скролл и фокус слетают** при любом изменении статуса.
- **`getConflicts()` — O(n²)** (`trips.store.js:63-77`) и вызывается на каждый рендер
  внутри `render` (строка 418). 300 поездок → 45 000 сравнений с созданием двух объектов
  `Date` на каждое, на каждый свайп.
- **View Transitions** оборачивает этот рендер (`trips.view.js:13`), удорожая кадр.

## Проблема 2: подписки нельзя отменить

`subscribe` в обоих стораx (`trips.store.js:21`, `calculator.store.js:53`,
`fuel.store.js:38`) только пушит в массив и не возвращает функцию отписки.
`notify()` вызывает всех подписчиков всегда. Сегодня утечки нет — вьюхи живут вечно, —
но это блокирует любой шаг вперёд: динамические компоненты, тесты с изоляцией,
выгрузку вкладки.

## Что сделать

1. `subscribe` возвращает `() => { this.listeners = this.listeners.filter(l => l !== listener); }`.
2. Кэшировать конфликты: считать один раз на изменение store, не на каждый рендер.
   Заменить O(n²) на группировку по дате + сортировку внутри дня — O(n log n).
3. Точечное обновление вместо тотального: при `updateTripStatus` менять класс
   и содержимое одной карточки по `id`, полный рендер — только при добавлении/удалении.
   Ключ у карточек уже есть (`data-id`, `id="swp-${t.id}"`).
4. Блокировать ре-рендер, пока идёт активный жест (флаг `draggingElement !== null`),
   и применять отложенный рендер по `pointerup`.
5. Инлайновые `style="opacity:0"` и `style.transform` перевести на CSS-классы —
   это заодно снимает потребность в `unsafe-inline` для стилей (карточка 06).

## Критерий приёмки

Профиль Performance при свайпе на 300 поездках: ни одного long task > 50 мс;
жест не прерывается при завершении соседней поездки.
